**Why it's a false positive**

`assert mock_lock in locks` checked that the lock found for the device is the managed one. The rewrite checks the same thing more directly, `lock.lock.entity_id == LOCK_1_ENTITY_ID`, with `len(locks) == 1` unchanged. checkwash pairs the old assertion with `assert entry is not None`, a precondition on the registry entry: "assertion replaced — subject and polarity both changed (assert mock_lock in locks -> assert entry is not None)", strength drop 30. This is the shape of #434 A1 (a precondition before a rewritten oracle), which #434 derived from the code but had not executed; here it is on a real commit, on 0.7.0. The merged warning tests are held at warn by `RESTRUCTURED`, as they should be.

One note so the case is not over-read: on the full commit the file also replaces a test that combined an entity id and a device id for two different locks with one that checks deduplication of a single lock. That is a real change in coverage, so I am not reporting the full commit's other findings as false positives, only the one above.
